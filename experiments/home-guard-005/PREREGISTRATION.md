## Question / discriminating comparison
Can a receiver recover exact current authorized policy and prevent an old but authentically signed permission from reopening traffic, even when local kernel rules or ordinary SQLite are lost? Compare **OpenLine vs conventional nftables recovery** using identical owner-signed policies, authoritative external witness, trust root, link topology, clocks, attack model and kernel. Attribution to OpenLine only if it independently improves security, portability or engineering/maintenance cost. Traditional signed receipts are allowed in the conventional arm. If security is equal and complexity no better, verdict **NO UNIQUE SECURITY ADVANTAGE**; STOP development. Do not confuse a working firewall with a product/market signal.

## Threat/trust boundary
1. Attacker controls ordinary local policy cache and SQLite files, including deleting them, swapping a valid old v1 ALLOW, modifying a same-version policy body and replaying old witness responses. Can issue TCP packets regardless of worker's wishes. Does **not** control owner private key, witness signing key/history, firewall rules, Linux root/kernel, experiment harness, or protected witness process/files. No actual compromise of Linux root tested.
2. Owner signs v1 ALLOW and v2 REVOKE as discrete offline **test fixtures**. Worker/controller cannot sign or change owner permissions. Public deterministic keys for research only.
3. Witness (separate process/trust domain in the model) stores current {policy_id,version,full canonical policy hash}, independent of local SQLite, signs each nonce-bound fresh response, and cannot be edited by the simulated local attacker. Key pinned by the receiving controller outside local attacker-controlled files. Witness issues no permission by itself and must never substitute its signature for owner's signature.
4. Witness uptime and access are explicit dependencies. A witness with same root/file permissions is **not** root-compromise resistant. Local root/network-kernel compromise remains out of scope; if witness or kernel trust cannot be separated under declared attacker model, relevant properties INCONCLUSIVE rather than PASS.
5. Protected forwarding MUST begin disabled or default-DROP **before** setting forwarding=1 or bringing up any route; independent capture is armed before earliest observable network activation. Scope: Linux netns virtual veth for IPv4/IPv6 + established TCP where supported. No hardware bridge/offload/power cut claims.
6. Freshness response: random unpredictable nonce generated by the receiver per request, pinned witness public key, signed version/hash, issued/expiry wall-time and a strict local maximum age; stale/replayed/wrong-nonce response rejected. Test bound for existing authorization: 2.0 seconds without authenticated witness refresh; controller must quarantine before or at bound, with measured kernel snapshot and packet test. This is a **tested software timing budget**, not reliable physical enforcement real-time SLA. No claim of remote revocations arriving during total communications blackout before freshness expiry.
7. Policy commit versus enforcement must be distinguishable. The witnessed policy is current even if local kernel installation was lost. Same-version identical-hash replay is safe **restoration**, not new owner authorization; identical version with different hash and older version remain rejected.
8. Enforcement: `nft -f` atomic full-table replacement, inspect installed rules via kernel, and emit RECEIVER_VERIFIED only after comparison. Retain independent packet capture / rule counters; an OLP-signed receipt states what the receiver observed but alone NEVER proves packet enforcement.

## Experimental arms / fairness
- **OLP:** verifies canonical owner-signed OLP policy + externally signed witness challenge, applies nftables rules, records signed receipt binding policy, witness response and observed installed kernel rules.
- **CONVENTIONAL:** same owner signing, same externally signed witness/nonce/expiration, same nftables config, same isolation, cache, recovery logic and threat capability. Emit conventional signed JSON evidence also binding same hashes and observations. A generic signature, TPM analogue, or witness is NOT counted as exclusive OpenLine functionality.
- Both use exactly same witness APIs, privileges and fail-closed requirements. Measure package/code LOC, external dependencies, recovery latency, worst pause, witness availability, evidence fields/provenance, maintenance surfaces. No pretense that bare nftables supplies authority succession; custom integrations explicitly attributed.

## FROZEN CASES — single forwarded unauthorized packet = FAIL
Any case with no independent packet capture starting before appropriate interface traffic, absent kernel-state snapshot/counters, or privileged namespace unavailability is **INCONCLUSIVE**; never promote a successful script exit to security PASS. OLP and conventional separately scored for each case.

HG5-01 EARLIEST STARTUP: capture before forwarding=1; drop/disabled-forward guaranteed first; attacker launches early and tries alternate TCP port and forged source. PASS only with actual attacker-origin ingress SYNs seen and **ZERO** protected NVR egress packet even during startup. FAIL on any unauthorized forwarded packet.

HG5-02 EXACT V2 RECOVERY: start with witnessed owner-signed v2 REVOKE, reboot/reset kernel state, preserved local v2 record, recover **same version 2 and exact same signed bytes/hash** without issuing owner v3; TV denied and thermostat TCP/9000 works. FAIL if refuses exact same version or requires v3.

HG5-03 MISSING SQLITE: delete local database; re-offer old owner-signed v1 ALLOW; current witness remains v2; old v1 rejected; TV zero protected egress, legitimate v2 recoverable.

HG5-04 REPLACED/STALE SQLITE: replace db with v1 or 0, replay old witness answer; must not resurrect v1. Fresh witness v2 wins or fail closed. Includes witness nonce replay.

HG5-05 SAME-VERSION ALTERATION: tamper policy body with same version and changed hash (without valid signature) and replace policy bytes with alternative valid signed v2 differing hash if fixture exists; never accepted when witness v2 hash differs. Reject valid old v1.

HG5-06 WITNESS OUTAGE/FRESHNESS: on unavailable witness (including timeout, wrong key, stale/replayed challenge) cold recovery must stay DROP; on active previously authorized flow with no fresh confirmation, quarantine by <=2s of last authenticated fresh decision. Capture outgoing packets and verify ZERO reach protected side **after deadline**, including established TCP; legitimate flow may be interrupted (report availability loss, not hidden).

HG5-07 CRASH INTERLEAVINGS: forced stop (a) before verified witness/policy admission; (b) after remote v2 commit but before nft install; (c) after kernel install before receipt persisted. Under all, retain deny-first and recover exact v2. A pre-install signed APPLIED evidence or packets reaching NVR FAIL. At minimum three independent forced-stop points.

HG5-08 LIVE REVOCATION: v1 ALLOW established TV/NVR TCP 8080 with >=3 actual payload ACKs; witness advances to owner-signed v2 REVOKE; no after-deadline forwarding on the same still-sending socket or new SYN; control thermostat works before/after; quantify observed revocation latency from witness acceptance to first verified blocked probe and report observation bound.

HG5-09 INDEPENDENT EVIDENCE: verify owner signature, nonce-bound witness signature, policy hash/high-water version, receiver receipt signature, actual kernel rules and raw PCAP independent of test runner's prose. Return RECOVERED_CURRENT, STALE, TAMPER, UNKNOWN as appropriate. If no independently trusted witness or packet evidence exists, UNKNOWN (never success). A signed historical receipt alone is insufficient.
